# Contributing

Contributions are welcome: specifications, schemas, conformance vectors, implementations, adapters, reproducible failures, documentation, and independent evaluations.

Before opening a pull request:
- Search existing issues, proposals, standards, and implementations.
- Explain the problem, intended users, and why existing approaches are insufficient.
- Identify original work, adaptation, or integration.
- Confirm redistribution rights and preserve required attribution.
- Exclude private material, credentials, personal data, and unpublished third-party work.
- Add tests and document limitations.

Pull requests should include the problem, proposed change, relevant references, tests and results, compatibility implications, security considerations, and licensing/provenance information.

AI-generated contributions are welcome when disclosed. The submitting person or organization remains responsible for the contribution. Agents must not merge their own changes or receive write credentials as a condition of participation.

Do not disclose exploitable vulnerabilities in public issues. Follow SECURITY.md. Maintainers may request evidence, independent review, revisions, or decline work that duplicates existing standards without a clear interoperability benefit.
